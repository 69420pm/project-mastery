## Findings

Ranked by money or quality at stake.

### 1. The map pipeline reached the user broken on the deployed model, three times: $25 of fixes after #248 alone

- **Evidence:** after PR #252 was ready, the user ran the gold course on Vercel and needed seven sessions ($25.05) to get through it:
  - MiMo calls through the Gateway timed out (`42456fd7`, `e88fb53a`).
  - A NUL character in model output failed every jsonb write (`c3419cdb`).
  - A failing match call failed the whole build (`3bd5eb00`).
  - The `grade` tool made every field optional, so MiMo sent `{help, finalValues}` without `results` four times, and the tool's error text reached the Student (`9ef6f454`).
  - #222 before it ($172) was followed by #228/#229 (slices 12–19) and then #248 itself, both from gold-run reviews.
- **Cause:** nothing local behaves like MiMo:
  - #248's spec ran every smoke check on flash-lite and kept MiMo to the gold run.
  - The gold run failed on 170 s timeouts during the build (`3f40b60a/a98bd850`). Per the spec, a report followed rather than a stop. The user called the $4.78 report on a failed build "basically useless" (`e88fb53a`).
  - The mock fills structured output with required fields only, but writes tool calls by hand with every field (`src/lib/ai/mock-provider.ts`, `mockTutorQuestions`). So no test sees a model leave out an optional field the code needs.
- **Fix:**
  - The mock keeps only a tool's required input fields, so a handler that needs an optional one fails in unit and e2e tests. The `grade` fix made its fields required; this guards the next tool.
  - NUL stripping is already global (`c3419cdb`).
  - Timeouts and match retries are product work, already merged.
  - Record: a gold report on a build that did not finish is not worth an Opus agent.
- **Applied** (the mock part) in `src/lib/ai/mock-provider.ts`. A new unit test passes with the change and fails without it: given a tool whose `prompt` is optional, the mock's `ask` call leaves `prompt` out. `pnpm check` passes, and so do `e2e/end-session.spec.ts` and `e2e/chat.spec.ts`. The tutor's real tools need every field the mock sends. The next retro should check whether a tool with an optional field the code needs fails in tests now.

### 2. Opus builders cost about $287 of these runs, driven by turns × context

- **Evidence:** 11 builders cost $8–18.56 each, at 145–235 turns and 277–366k peak context, with three compactions (`3514e2e8/aaf46982`, `3f40b60a/a4402337`, `493644b5/a0256c49`).
  - #248 slice 5 spent about 120 of its 222 turns on edits and typechecks across the whole tutoring rewrite.
  - #222 slice 1 spent about 65 turns removing the old build and 50 fixing tests.
  - Cache reads are 55% of a builder's cost and are priced the same on Sonnet and Opus. Output and cache writes, the other 45%, cost half as much on Sonnet.
  - The seven Sonnet slices cost $0.42–2.29, and no review finding or later fix traces back to one.
- **Cause:** `/to-spec` marks a slice `sonnet` only when it "follows a pattern the codebase already has", so about 1 slice in 6 runs on Sonnet. The epics also bundle 10–19 slices into one PR, beyond `/to-spec`'s limit of four, which is the user's choice for these epics.
- **Fix:** make `sonnet` the default in `/to-spec` and keep `opus` for slices that design new structure (a new workflow, schema or model call). Running every builder on Sonnet would have saved about $60 here. Leaving Opus on the design slices would cut that to about $35. Quality risk: Sonnet has not built a large design slice here yet.
- **Not applied** (the maintainer's choice).

### 3. `pnpm -s agent up` starts the app on the live provider: 2 builders made real model calls by accident

- **Evidence:** `31c1ed5c/a3c64302:L691` (one flash-lite reply, $0.004) and `3717714a/a3cf6a6d:L1325` (several calls during a runtime check). Both reported it themselves.
- **Cause:** `startDevServer` passes on the environment, and `next dev` reads `AI_PROVIDER=gateway` from the linked `.env.local`. `live-ai.md` says runtime checks use the mock, but nothing enforces it.
- **Fix:** `agent up` starts `next dev` with `AI_PROVIDER=mock` unless `AI_PROVIDER` is set in its environment. The Bash guard requires `ALLOW_LIVE_AI=1` for `AI_PROVIDER=gateway … agent up`, as the gold run does.
- **Not applied** (the maintainer's choice).

### 4. Live runs and builders share the local database

- **Evidence:**
  - #248 slices 5, 6 and 9 hit pgTAP failures caused by the gold course's rows: duplicate `chapter_extractions_pkey` and unscoped fixture queries (`3f40b60a/a4402337:L1342–1368`, `a9a000be:L684`, `a5806546:L685`). They spent about 7 turns each and moved on with a red `db:test`. The finish job then spent about 15 turns scoping the queries (`a3771617:L912–1044`).
  - Slice 5 applied a migration that dropped `map_findings` while the gold build ran (`a4402337:L184`), and the gold agent then saw the table missing (`a98bd850:L582`).
  - #222's finish ran `db:test` while its own background smoke check wrote to the database (`9ec74b7a/a3a22ff6:L1112`).
- **Cause:** one local Supabase for everything. `worktrees.md` says so, but a red `db:test` gives no hint that another run's rows caused it.
- **Fix:** none now. #248's finish scoped the queries, and no pgTAP file counts a table without a filter today. The next retro should check whether `db:test` still fails on other runs' rows.

### 5. `pnpm -s retro` lists only the newest 20 sessions

- **Evidence:** this retro needed the list back to 2026-10-15, about 110 sessions, and had to patch the CLI to get it.
- **Fix:** `pnpm -s retro --since <YYYY-MM-DD>` lists every session since that date.
- **Not applied** (the maintainer's choice).

### 6. The shell-write guard blocks writes to the scratchpad

- **Evidence:** coordinators editing the PR body with `sed -i` on a scratchpad file (`3f40b60a:L604`, `3717714a:L220,L224`, `ec9c18d2:L196,L201`), and builders writing a scratch note (`3f40b60a/aeee1ce4:L191`, `493644b5/a0256c49:L273`). That is 7 wasted turns, mostly on Haiku.
- **Cause:** the guard is there to keep repo files on the lint hook, but it matches any `sed -i` or `cat >` target.
- **Fix:** skip the guard when every write target is under `/tmp/`.
- **Not applied** (the maintainer's choice).
