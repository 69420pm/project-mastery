## Findings

Ranked by money or quality at stake.

### 1. Waiting over 5 minutes on a smoke check rewrote a builder's whole context: $11.06

- **Evidence:** in the turn after a wait of 5 minutes or more, the cache read is 0 and the whole context is written again at Opus's 5-minute write price:
  - #83 slice 2 had eight rewrites of 144–186k tokens, $6.80 of its $11.63 (`d088f6c1/acd91ccd:L335`–`L589`).
  - #83 finish had four, $1.40 (`d088f6c1/ad4e09b9:L137`–`L172`).
  - #85 slice 1 had two, $1.49 (`5c8135c1/a7858278:L322,L352`).
  - #85 finish had three, $1.37 (`5c8135c1/a413c0ce:L244,L269,L297`).
  - No other agent in the six runs had such a gap. Coordinators use the 1-hour cache, so waiting on builders cost them nothing.
- **Cause:** `pnpm smoke map` ran on MiMo through DeepInfra, which on 2026-10-14 needed about 3 minutes per call or hit the 5-minute headers timeout. Builders waited on it in 10-minute `until` loops or `tail -f` with `timeout 590`. A subagent's prompt cache expires after 5 minutes idle, and the smoke runner has a call cap but no time limit. #91 has since moved local smoke checks to Gemini flash-lite, which answers in seconds, but `AI_SMOKE_MODEL` and slow hours still allow any wait.
- **Fix:** have `evals/smoke.ts` stop a check after 4 minutes (`AI_SMOKE_MAX_MINUTES`). When it stops, it should list the calls recorded so far and say the check is not verified. Add the 5-minute cache fact to `docs/agents/live-ai.md`.
- **Applied.** With `AI_SMOKE_MAX_MINUTES=0.05`, `pnpm smoke priority` stopped after 3 s with exit 1 and listed the calls so far. With the default limit it passed in 1 call ($0.0008).

### 2. Structured-output calls failed on the deployed model only: four escapes

- **Evidence:**
  - #96: on the Vercel preview, MiMo answered the parse's page call with 702 reasoning tokens and 2 text tokens, and `Output.object` threw. #97: the `exercise` call failed the same way.
  - #86's slice 2 had found this on the `priority` call and written it into `docs/agents/notes/ai-sdk.md` (`aadece43/afaec81e` handoff). The sibling calls kept default reasoning, and the next deploy broke the parse.
  - Two more failures showed only on Vercel: #82 (hosted Supabase does not grant `service_role` on new tables) and #87 (no system fonts, so the page images were blank).
- **Cause:** checks run on the mock locally, and since #91 also on Gemini, so nothing local behaves like MiMo. `live-ai.md` asks for a provider behaviour found live to be added to the mock, and #86 added only the note.
- **Fix:** the mock provider fails a structured-output call whose `reasoning` is not `"none"`, with a message naming the note. Every call sets `"none"` since #97, so the tests stay green, and a new call without it fails in e2e and `run-app`. #82, #87 and the canvas half of #96 are fixed, with notes; record only.
- **Not applied** (the maintainer's choice). The next retro should check whether a new structured-output call ships without `reasoning: "none"`.

### 3. The shell-write guard refuses plain reads: 6 wasted turns

- **Evidence:** `becd1710/af5f9985:L109`, `2d26c669/a12dd705:L23`, `2d26c669/aafd8d57:L28` (a read-only reviewer), `5c8135c1/ac2be169:L250`, `5c8135c1/a413c0ce:L197`, `5c8135c1/a7da48a5:L18` (a reviewer). Each was `sed -n …` followed later in the line by `grep -i`.
- **Cause:** in `guard-bash.sh`, `sed\s+(\S+\s+)*-i` lets `\S+` cross `;`, `&&` and `|`, so a later command's `-i` counts as sed's. The same applies to `perl`.
- **Fix:** stop the option match at a command separator.
- **Applied.** The four commands quoted above now pass, as does `sed -nE`. `sed -i`, `sed -E -i`, `sed -i.bak`, `cat >` and Python heredocs are still refused. `perl -pi`, which the old pattern let through, is now refused too.

### 5. Removing the worktree after a merge takes another session turn every time

- **Evidence:** the user asked the coordinator to remove the worktree after #69, #70, #83 and #84. `ExitWorktree` refused each time because the branch has commits, and had to be called again (`becd1710:L260`, `15e3d4ce:L185`, `d088f6c1:L250`, `2d26c669:L181`). #69 also needed a list of commands to run next time. #70 found an uncommitted draft in the main checkout.
- **Cause:** PR #46's `tools/spec-run/cleanup.sh` was deleted in #65, and `/build` has no replacement.
- **Fix:** add `tools/build/cleanup.sh <issue>`. It removes the worktree only when its PR is merged, then deletes the branch, prunes and pulls `main`. `/build`'s report names it.
- **Applied.** Tested: it refuses to run outside the main checkout and rejects a non-numeric issue. Not run: the removal itself, and keeping a worktree whose PR is unmerged or that has uncommitted changes. No build worktree existed to try them on.
