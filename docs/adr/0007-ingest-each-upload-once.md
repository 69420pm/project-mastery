# Ingestion: process every upload once

**Context.** Grounded answers need citations down to the slide or page. Course PDFs in STEM are full of formulas, diagrams and scanned exams, which plain text extraction loses. Not every model accepts PDF files directly, but most current models accept images.

**Decision.** Ingest each upload once in a background workflow: render each page to an image, convert it with a vision model to markdown with LaTeX, split it into chunks that keep their page reference, embed the chunks into pgvector, and derive the topic map. Every feature reuses this result.

The parse makes three kinds of model call: two on the `ingest` task, described next, and an embedding call on the `embed` task (see below):

- **One vision call per page.** It gets the page image (a PDF page rendered to PNG at scale 2 from the stored file for that call and not kept, or the uploaded image itself) and returns structured units: markdown in the source language with LaTeX formulas and Mermaid for flowcharts and trees, one of seven labels (content, definition, example, exercise, solution, figure, admin), an optional exercise number and points, an optional figure with a description and a box normalized to the page, and whether the unit continues across a page break. Each page's result is stored, so a retried parse skips finished pages.
- **One text call per file.** It merges units into chunks across page breaks, splits exercises into subtasks and recognises old exams, working on unit ids so the markdown is not generated twice. Code checks that every unit lands in exactly one chunk of neighbouring units and every page is covered, or the step fails and retries; the chunks then replace any earlier ones in one transaction (`public.replace_material_chunks`).

The chunks are then embedded (`embedMany` on the `embed` task, only chunks without a vector, in batches so a retry loses little), and the parse ends with a pairing pass: every exercise subtask of the Course is paired with its solution chunk, or "no solution". Pairing runs on every parse and after every delete of a Material, and is recomputed for the whole Course, so upload order does not matter. It matches by normalized exercise number first, then sends what is left in one content-matching text call on the `ingest` task. A pass takes a request number first (`request_exercise_pairing`) and writes only while it is still the Course's latest request (`replace_exercise_solutions`), so of overlapping passes only the last writes.

Page images and figure pictures are not stored: a PDF stays the only copy of its pages. A figure keeps its page and the model's box, padded and checked by code (the whole page as the fallback for a bad box), and its description. The chunk view shows only the description, as text (#115): it shows what the parse extracted, so the browser crop of the Material's file was dropped. The page and box stay stored, so a crop or a jump to the figure's page can come back without a re-parse. The starting model is `xiaomi/mimo-v2.6-flash`, a cheap vision model that reads page images (not PDF files) and lets whole scripts be parsed on the Gateway's monthly free credit; the task can move to a flash model in `src/lib/ai/models.ts` when real material needs it. Every call is recorded against the Student's Daily limit, and there is no page cap.

The Knowledge map, like parsing, processes each chunk once (#83): an update maps only the chunks not yet recorded in `knowledge_map_chunks`, adds what they teach to the stored map, and drops what deleted chunks taught. A re-parsed Material's chunks are new, so they are mapped again.

**Consequences.** Works with any vision model, so the ingestion model can change freely. Ingestion cost is paid once per upload, not per question. The exact conversion model is chosen by testing on real course materials. Until chunks are used in Chats, Chats send attached Materials raw, as inline files, on every turn, so they are paid for again with each message.
