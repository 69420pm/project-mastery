# Ingestion: process every upload once

**Context.** Grounded answers need citations down to the slide or page. Course PDFs in STEM are full of formulas, diagrams and scanned exams, which plain text extraction loses. Not every model accepts PDF files directly, but most current models accept images.

**Decision.** Ingest each upload once in a background workflow: render each page to an image, convert it with a vision model to markdown with LaTeX, split it into chunks that keep their page reference, embed the chunks into pgvector, and derive the Knowledge map. Every feature reuses this result.

The parse makes vision calls on the `ingest` task, one per page, and embedding calls on the `embed` task (see below). There is no call over the whole file: chunks come from the units in code, so no prompt grows with the Material (#223).

- **One vision call per page.** It gets the page image (a PDF page rendered to JPEG with a 2,000-pixel long edge from the stored file for that call and not kept, or the uploaded image itself) and, when the PDF has a text layer on the page, that text as a hint: it may be out of order and garbles formulas, so the image wins. It returns the page's language and its units: markdown in the source language with LaTeX formulas, a plot or drawing described in a `**Figure:**` blockquote, one of four labels (content, exercise, solution, admin), the exercise number as printed, and whether the unit continues across a page break. Page furniture is not transcribed: running headers, footers, page numbers, logos, title pages, tables of contents, indexes and reference lists. Each page's result is stored, so a retried parse skips finished pages.
- **Skipped and unreadable pages.** Code skips a slide overlay (a page whose text layer starts the next page's) and a blank render without a call. A page whose call still fails after its retries is stored `unreadable` with no units, the parse goes on, and the Materials page lists it. A reached Daily limit still fails the parse.
- **Steps.** A read step opens the PDF once and reads up to 8 pages, a few calls at a time, and starts no call after 150 seconds, so it ends within Vercel Hobby's 300-second limit. Every step sets the Material's heartbeat; a parse without one for 30 minutes counts as failed, so the Student can start it again.

- **Chunks and Parts in code.** Code joins a unit to the previous page's last non-admin unit when a continuation flag and the text agree, up to 6,000 characters and 3 pages; admin units stay single. It finds each chunk's chapter from the PDF outline (or level-1 headings) and groups the non-admin chunks into Parts: teaching Parts by heading, merged under 400 and split over 4,000 words, and exercise Parts by root exercise key. Chunks and Parts are stored in one transaction. A Part is the unit the map build reads, so no build prompt grows with a Material.

The non-admin chunks are then embedded as documents (`embedMany` on the `embed` task with Cohere's `search_document` input type, only chunks without a vector, in batches so a retry loses little); admin chunks are never searched or paired, so they get no vector. The parse ends with a pairing pass: every exercise subtask of the Course is paired with its solution chunk, or "no solution". Pairing runs on every parse and after every delete of a Material, and is recomputed for the whole Course, so upload order does not matter. It matches by normalized exercise number first, then sends what is left in one content-matching text call on the `ingest` task. A pass takes a request number first (`request_exercise_pairing`) and writes only while it is still the Course's latest request (`replace_exercise_solutions`), so of overlapping passes only the last writes.

Page images and figure pictures are not stored: a PDF stays the only copy of its pages. A figure is its description in the unit's Markdown. The starting model is `xiaomi/mimo-v2.6-flash`, a cheap vision model that reads page images (not PDF files) and lets whole scripts be parsed on the Gateway's monthly free credit; the task can move to a flash model in `src/lib/ai/models.ts` when real material needs it. Every call is recorded against the Student's Daily limit, and there is no page cap.

The Knowledge map, like parsing, processes each chunk once (#83): an update maps only the chunks not yet recorded in `knowledge_map_chunks`, adds what they teach to the stored map, and drops what deleted chunks taught. A re-parsed Material's chunks are new, so they are mapped again.

**Consequences.** Works with any vision model, so the ingestion model can change freely. Ingestion cost is paid once per upload, not per question. The exact conversion model is chosen by testing on real course materials. Until chunks are used in Chats, Chats send attached Materials raw, as inline files, on every turn, so they are paid for again with each message.
