# Questions as first-class objects

**Context.** Until M1 (#173) the AI recorded evidence with one `recordAttempt` call per problem: a correct-or-not flag per KC, written after the fact and tied to nothing in the Chat. Nothing linked an attempt to the question that was asked or the answer that earned it, so grading could not be checked, a numeric answer could not be compared with the Exercise's key, and later modes (review, practice, mock exams) had no session to belong to.

**Decision.** Three owner-only tables replace the old log. `study_sessions` holds one row per Chat (`chat_id` unique), started by a database trigger when the Chat is inserted, with its Course, `mode` (`learn`, `review`, `practice`, `mock`, `results`), `topic_id` and `stage`, and `started_at`/`ended_at`. Since M4c (#180) a learn session's first reply fixes its `topic_id` to the plan's next Topic and sets its start `stage` (`review`, `orient`, `prime`, `read`, `work`, `apply`, `rebuild` or `close`); both stay null in a Course without Topics. The Student never writes either column: the security-definer functions `start_study_session_topic` (once per session) and `set_study_session_stage` (not past `close`) write them on the caller's own running session, and the order of stages is checked in code. Since M6 (#184) the Chat's first request can switch `mode` from `learn` to `review` or `practice` through the security-definer function `start_study_session_mode`, only on the caller's own running session while it has no Topic and no question; the Student never writes `mode` otherwise, and only learn sessions get a Topic and stages. A Student may update only `rating` (1 to 5), `rating_note` (at most 300 characters) and `ended_at` on their own session. `questions` holds each graded question the AI asks in a session: its `kind`, Markdown `prompt`, optional Exercise, the Student's answer (`answer_text`, `answer_message_id`) and when it was asked, answered and graded; its KCs are in `question_kcs`. `attempts` is recreated as the grade of one question on one of its KCs: `kind` (`pre` or `learn`), `result` (`full`, `partial`, `wrong`), `help`, and `check` (`match`, `mismatch` or null) for the numeric comparison. Row Level Security lets a Student add attempts only on KCs their own question tests, in that question's session, and never change one. A deleted Chat leaves its session (`chat_id` set null), so the learning evidence survives; a deleted Course takes everything. A Course's attempts are read through their session's `course_id`. The review ladder read `full` as correct and `partial` and `wrong` as incorrect until FSRS replaced it in M2; ADR 0019 supersedes that reading with FSRS ratings.

**Consequences.** The migration deletes every Chat and attempt, which were test data, and drops `chats.model_choice` with the Chat's model picker: the Chat runs on one model. Reads of a Course's attempts join `study_sessions`. Grading, the numeric check and evals can now point at a stored question and answer. Exercises gain `final_answers` for the numeric check; those analysed before stay null until their map is rebuilt.
