# React Flow and ELK for the Knowledge map graph

**Context.** The map page shows a Course's whole Knowledge map as an interactive graph (#118): Big ideas holding their KCs, Exercises and Prerequisites. Its nodes show badges, icons and Markdown, so they should be React components styled with the design system ([ADR 0011](0011-shadcn-ui-with-own-design.md)). The layout must follow learning order and keep each Big idea's KCs together while Prerequisites cross between Big ideas, which is compound (nested) layered layout.

**Decision.** Draw the graph with React Flow (`@xyflow/react` 12) and lay it out with ELK (`elkjs` 0.12): the `layered` algorithm, left to right, with `elk.hierarchyHandling: INCLUDE_CHILDREN` so edges between KCs of different Big ideas take part in one layout. Each Big idea is a React Flow parent node; ELK returns child positions relative to their group, which is what React Flow's `parentId` expects. ELK runs in its own web worker (`elk-worker.min.js`), and the graph shows a skeleton until the first layout. Turning the map into the ELK graph is pure code in `knowledge-map/domain`. Rejected: Cytoscape.js, whose nodes are not React, and d3 with dagre, which has no compound layered layout and leaves rendering, zoom and interaction to us.

**Consequences.** Two client dependencies, loaded only on the Course map (`courses/[courseId]/map`, where the Course's home redirects) and the Topic page (`map/[topicId]`). The layout runs off the main thread, so a large map does not block the page, and it reruns only when the graph's nodes or edges change, not on every poll. ELK's layered layout is deterministic for the same input, so a map keeps its shape across visits. The verified ELK facts are in `docs/agents/notes/react-flow-elk.md`. React Flow shows its attribution link, which only a paid plan may hide.

**Update (#176).** The Course map draws Topics with the same stack, as compound nodes: each Big idea a parent node holding its Topics' cards.
