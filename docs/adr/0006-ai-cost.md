# AI cost: the Gateway's free credit in development, metered in production

> Local development: the development parts of this ADR are superseded by [ADR 0016](0016-gemini-api-for-local-development.md), which moves the text tasks to the Gemini API free tier. Preview and production are unchanged.

**Context.** There are no users yet, so development should cost close to nothing. AI Gateway gives every team a free monthly credit ($5), with lower rate limits than paid use, but only with a credit card on file. Bring-your-own-key requires the paid tier, and buying credits ends the free credit for good. The Gemini API free tier, which development used before, has no card requirement but far tighter limits (20 requests a day on the larger models), and Google may use its prompts for training and human review. At MiMo V2.6 Flash prices ($0.14 per million input tokens, $0.28 output) the free credit buys tens of millions of tokens a month. A public deployment must not be drainable by a single Student.

**Decision.** Every environment goes through AI Gateway: local development with an `AI_GATEWAY_API_KEY`, deployments with OIDC. Development has no provider of its own, so what is tested locally is what runs in production. The default model of the text tasks is `xiaomi/mimo-v2.6-flash`, cheap enough that development can use real models freely; embeddings use `cohere/embed-v5.0-fast`. The free credit serves only some models (no Google model, verified 2026-10-14), so the other model choices are among those it serves. MiMo calls are pinned to its DeepInfra provider with the Gateway's `only` option, because DeepInfra is the only one of its six providers that honors the JSON schema of structured output, and the only one with zero data retention and no prompt training; `only` also excludes gateway fallback models, so these tasks have none. Development uses only test materials without personal data. Unit tests and CI use mock models and make no real calls. End-to-end tests run the app with `AI_PROVIDER=mock`, which answers every task with deterministic replies and is refused on Vercel. Production moves to purchased credits, with budgets per project and API key. Before real users, production tasks are restricted to providers with zero data retention and no training on prompts.

Cost is computed in US dollars from a static price table (USD per million input, output and cached-input tokens) for every model any task can call, so the free credit is priced as if it were paid. A model without a price is an error. Each AI call is recorded with its Student, task, model, token counts and cost, and a Chat reply's record also with the reply's id, so the Chat shows what each reply cost. The model is the one that answered, which would be a gateway fallback when the primary failed and the task set one. When a call is aborted or fails mid-stream, providers report no usage, so its cost is estimated at about four characters per token and recorded as estimated. Each Student has a Daily limit in dollars (`AI_DAILY_LIMIT_USD`, unset means no limit): today's spend since 00:00 UTC is checked before each AI call, and a call that has started always finishes. AI Gateway's reported cost is not used: it would be a second source of truth next to the price table.

**Consequences.** Local development and preview deployments need AI Gateway set up, and the free credit is shared by all of them, so the $5 a month is the development budget (the Gateway dashboard shows what is left). Every AI call retries with backoff (AI SDK `maxRetries`, honoring `retry-after`), and AI Gateway can fall back to further models configured for a task: the configuration supports fallbacks, but no task sets one. Token usage and cost are recorded per Student and per AI call from the first AI feature, which also provides the metering [VISION.md](../../VISION.md) requires. Prices are maintained by hand: adding or changing a model means adding its price, and recorded cost can drift from the bill when providers change prices or price long prompts higher. One reply may overshoot the Daily limit. The $5 is split into three buckets: Study 60% (tasks chat, brief, title, ingest, map, exercise, embed and priority), Generation 15% (no task yet) and evals 25%. The `/usage` page shows a Student's spend this UTC month in the first two against their shares, with a breakdown by Course; spend outside a Chat has no Course and shows as one row, and eval spend is in `pnpm evals:report`. The shares are a budget to read, not a limit that blocks calls. Without a fallback, an outage of DeepInfra stops the MiMo tasks. A text PDF attached to a Chat was read correctly by MiMo through DeepInfra, but the model list shows no file input for it, so scanned PDFs in Chats ([ADR 0007](0007-ingest-each-upload-once.md)) are unverified. Embeddings of different models are not comparable, so changing the `embed` model means re-embedding and a new column size.
