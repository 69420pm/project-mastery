# PDF page rendering and the parse workflow

Installed: unpdf 1.8.1, @napi-rs/canvas 1.0.11, workflow 5.2.2. Code: `src/features/ingestion/workflows/page-images.ts`, `parse-steps.ts`.

- **Native binding must stay external.** Bundled by Next.js (Turbopack), `@napi-rs/canvas` fails in a step with "Cannot find native binding". `next.config.ts` lists it in `serverExternalPackages`; Next's built-in list has `canvas` but not `@napi-rs/canvas`.
- **Rendering.** `openPdf` renders with pdf.js's `page.render` onto a canvas from the app's `@napi-rs/canvas` (`createCanvas`, passed as both `canvas` and `canvasContext`), scaled to a 2,000-pixel long edge, reads its pixels with `getImageData` for the blank check and encodes it with `canvas.encode("jpeg", 85)`; unpdf's `renderPageAsImage` only gives PNG. `getDocumentProxy` takes ownership of its buffer, so pass a copy. Hand-written fixture PDFs with inexact xref offsets still open. The text layer comes from `page.getTextContent()`: each item's `str`, plus a newline where `hasEOL`.
- **Fonts: use pdfjs-dist, with plain paths.** Rendering pages through unpdf's own bundled pdf.js lost all text on Vercel while figures and lines stayed. Its font and cMap loading uses `fetch()`, which cannot read local files, so a PDF without embedded fonts falls back to _system_ fonts, which a deployed function lacks; the same fallback hides the bug on a dev machine. In Next's production bundle unpdf's own `import.meta.resolve` setup also silently fails (`import.meta` is a plain object there). `page-images.ts` therefore loads the installed `pdfjs-dist/legacy/build/pdf.mjs` through `definePDFJSModule` and passes `standardFontDataUrl` and `cMapUrl` as plain paths with a trailing slash (pdf.js reads them with `fs`; a `file://` URL fails) and `useSystemFonts: false`. `pdfjs-dist` is in `serverExternalPackages`, and `outputFileTracingIncludes` in `next.config.ts` ships its `standard_fonts/` and `cmaps/` to the `flow` workflow route.
- **pdf.js gets the app's canvas.** pdf.js creates its own canvases for masks and patterns with `createRequire(import.meta.url)("@napi-rs/canvas")`, resolved from pdfjs-dist's folder in the pnpm store. The trace of the `flow` route ships the app's `node_modules/@napi-rs/canvas` but not pdfjs-dist's link to it, so on a Vercel preview on 2026-10-15 every page step failed with "Cannot find module '/var/task/node_modules/.pnpm/node_modules/@napi-rs/canvas/index.js'". Node had found a partial copy in pnpm's hidden hoisting folder. `openPdf` passes `CanvasFactory` from unpdf's `createIsomorphicCanvasFactory(canvasImport)`, so pdf.js never makes that call. Its import-time polyfill `require` still fails there, but only logs a warning ("Cannot load \"@napi-rs/canvas\" package"), and unpdf injects `DOMMatrix` and `Path2D` from the app's canvas instead.
- **One canvas copy.** pdfjs-dist depends on its own `@napi-rs/canvas`; two copies reject each other's `Path2D` ("Value is none of these types `String`, `Path`"). `pnpm-workspace.yaml` pins one version through a catalog and an override.
- **Nothing is stored per page.** `readPages` opens the Material's PDF once per step of up to 8 pages and renders each page for its call, then drops it. `preparePages` opens it once for the page count and the text layers.
- **Workflows locally.** Runs started from a Server Action execute in the dev server and in `next start`, with the local world. The proxy matcher must skip `/.well-known/workflow/`.
- **Vercel.** `@napi-rs/canvas` loads in a deployed `fra1` function. Text in the page images with the font fix has not been checked on a deployment yet: look at a page image in Langfuse after a parse.
- **Figures.** A page call describes a figure in its unit's Markdown; no box or picture is kept. `sharp` is used by tests only.
