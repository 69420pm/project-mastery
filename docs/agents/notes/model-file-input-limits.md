# File input limits: Gemini and AI Gateway

- **Gemini inline size.** `node_modules/@ai-sdk/google` 4.0.87 docs (`docs/15-google.mdx`, "File Inputs", lines ~314-375) give no inline limit for `generateContent`. The only "20 MB" figure is the Batch threshold (line ~1122): smaller batch bodies go inline, larger ones use the Files API. The docs say the SDK downloads URLs passed as data, except Gemini Files URIs (`https://generativelanguage.googleapis.com/v1beta/files/`) and YouTube URLs. Larger files: `google.files()` (`dist/index.d.ts`, `files(): FilesV4`) and `uploadFile` (`node_modules/ai/docs/03-ai-sdk-core/39-file-uploads.mdx`). Upload references are per provider. The 20 MB figure for `generateContent` is from memory and unverified.
- **Gateway URL handling.** `@ai-sdk/gateway` 4.0.103 sets `supportedUrls = { '*/*': [/.*/] }` (`src/gateway-language-model.ts:35`), so the SDK does not download URLs and the gateway receives them. File bytes are base64-encoded (`gateway-language-model.ts:~207`).
- **PDFs on non-Google models.** The gateway docs (`docs/00-ai-gateway.mdx`) say nothing about PDF or file input for any provider. The only input capability tag in `providerOptions.gateway.has` is `'vision'`, described as image input (`src/gateway-provider-options.ts:69-85`). There is no `pdf` or `file` tag. Whether `xiaomi/mimo-v2.6-flash` accepts `application/pdf` is not in the installed docs. Check it with one live call.
- **Repo.** `src/lib/ai/models.ts` (`AI_TASKS`) lists `xiaomi/mimo-v2.6-flash` as a fallback for chat and ingest. Ingest is meant to work from page images (ADR 0007), so no PDF is sent to a non-Google model there.
