# Tutor smoke check

Verified on 2026-10-25 on `google/gemini-3.5-flash-lite` (#182), two failing runs and one after the fixes:

- Since #205 every Chat of the check opens a staged learn session, and with due reviews it starts in the review stage. PR #205 did not run the check, and the learn eval (`evals/learn.ts`) starts every session at orient, so the review stage had no live coverage.
- The review and apply stage instructions said "ask one review question" and "ask one Problem's question" in plain words. The model read that as "write the question": it wrote the question as text, and the next turn called `grade` with an id it made up (`q_review_1`, `q_20261025_001`), which the tool refused. The prime stage, which says "ask with kind prequestion", called `ask` correctly. Naming the tool ("through ask, never as text") fixed the review stage in the next run.
- Asked for Ex. 7.2a in a new Chat, the model calls `findProblems`, then went on with the stage (review), or moved to apply with `setStage` and wrote the Exercise as text. The staged instructions now say to do what the Student asks for first, in any stage; the apply wording got the same fix as review. A second run with both still wrote Ex. 7.2a as text right after `setStage` to apply, so the `findProblems` description now says to pose the picked Problem through ask with its problemId: not yet verified live.
- In that second run the reply to "Done reading." opened the Topic's other Reading section instead of asking about the one read; the first run asked. The reading instructions now say to ask before opening any other section.
- Third run (372210f): the review, the Exercise through `findProblems` and `ask` by problemId, and its `match` check all passed. After "Done reading." the model again opened the other section, the study-text version of the same pages, without a question. The read stage ("open the first Reading section without a Done yet") and the work stage ("while a Reading section has no Done yet, go back to read") point at the second section, against the general reading rule; the check gives every Topic two sections of one chunk.
- Known gap of the staged sessions from #205: after "Done reading." the tutor may open the Topic's other section of the same pages instead of asking about the one read. Two possible fixes: count a section's other versions of the same pages as done once one is read, or let the read stage pick one section per set of pages. The check still sends "Done reading." (its reply counts for the no-ids check) but no longer asserts what follows.
- Fourth run, same feature code as the third: 7 checks failed. The model wrote the review question, the prequestion and Ex. 7.2a as text again, called `grade` with made-up ids, and named a section in text without `showReading`. So on `gemini-3.5-flash-lite` the "through ask, never as text" wording helps but does not hold from run to run: one run is no verdict on it.
- A reply's steps go over the free tier's 15 requests per minute (see `ai-sdk.md`), and a 429 cut a turn short. The smoke runner now holds each Gemini API request until the last minute has room for it (`AI_SMOKE_RPM`, default 14): the next run had no 429 and finished within the 4-minute cap.
